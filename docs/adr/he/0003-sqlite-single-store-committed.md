# קובץ SQLite אחד הוא המאגר היחיד, והוא נשמר ב-git

תהליך הקליטה (ingest) כותב הכול לקובץ `data/takam.db` דרך `node:sqlite`, המובנה ב-Node: המטא-דאטה, ההעשרה, ה-HTML אחרי ההמרה, הקטעים עם הווקטורים שלהם, וגם טבלה של יומן החיפושים. הקובץ נשמר ב-git, כדי שמי שבודק את העבודה יוכל להריץ את החיפוש, את מציג ההוראות ואת הבדיקות בלי מפתח API ובלי רשת.

שתי חלופות נדחו:
- **JSON לצד SQLite:** שני מאגרים שצריך לשמור מתואמים.
- **מסד נתונים וקטורי:** ציפינו לכ-200 קטעים ויש 376. חישוב cosine similarity ב-TypeScript פשוט מספיק לכמות כזו.

אינדקס החיפוש (MiniSearch) נבנה מחדש בזיכרון מתוך SQLite בכל הפעלה של ה-API. בייצור נעבור ל-Postgres עם pgvector (ראו README, חלק ג').
